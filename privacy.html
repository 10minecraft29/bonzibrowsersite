Privacy & security

Clear controls, clear boundaries.

What stays local, what can Sync, and what BonziBrowser’s built-in protections actually do.

Local browser data

History, bookmarks, downloads, profile settings, site permissions, extension state and browser caches are stored in BonziBrowser’s local Electron user-data directory unless a Sync category is explicitly enabled.

Bonztel Sync

Sync is optional. Depending on your choices, it can carry bookmarks, settings, optional history, device status and an encrypted password payload through the configured Bonztel account backend.

Password encryption

Password Sync uses an AES-256-GCM vault. A random vault key is wrapped by a master-password-derived key and separately by a recovery key. The master password and recovery key are not uploaded as plaintext.

Supabase publishable key

The built-in Supabase project URL and publishable/anon key are client-side configuration, not privileged secrets. Database security must rely on Row Level Security. Secret/service-role keys must never be shipped in the app.

BonziBlock

BonziBlock downloads filter lists, compiles supported rules locally and blocks matching requests inside the browser. The local network logger is intended for diagnostics and does not need Bonztel analytics.

BonziShield

BonziShield provides tracker blocking, tracking-parameter cleanup, HTTPS upgrades, site permission controls, Global Privacy Control/Do Not Track options and optional strict third-party blocking.

Filter sources

Third-party lists used by BonziBlock.

BonziBlock can use EasyList, EasyPrivacy and optional Fanboy anti-annoyance/cookie/social lists. List updates are downloaded as filter data—not executable remote JavaScript.

BonziBrowser should include the appropriate third-party notices/licenses alongside distributed builds. See the browser source and extension THIRD_PARTY documentation for the exact lists enabled in a given version.
